# EDSMAC4 Calculation Options

EDSMAC4 (Engineering Dynamics Corporation Simulation Model of Automobile Collisions, 4th Revision) is a simulation analysis of single or multiple-vehicle crashes. It is based on the program called SMAC developed at Calspan for NHTSA, and includes several major extensions and enhancements developed by Engineering Dynamics Corporation. EDSMAC4 uses a set of assumed or estimated initial conditions, including positions, velocities and driver controls, provided by the user for each vehicle. EDSMAC4 then predicts the outcome of a crash by simulating the vehicle trajectories and damage profiles.

The output generated by EDSMAC4 is a time history of the vehicle kinematics (position, velocity and acceleration), kinetics (summation of tire and collision forces and moments acting at the CG), and tire skidmarks for the duration of the crash sequence. The program also computes the resulting damage profiles, the Collision Deformation Classifications (CDC), Principal Direction of Force (PDOF), delta-V (a measure of crash severity) and peak acceleration for each damage range. EDSMAC4 also produces a collision pulse (acceleration vs time history) useful for occupant simulations, such as EDHIS.

Accident investigators can use EDSMAC4 to determine how the crash may have occurred. By repeated adjustments of the initial conditions and driver braking (or acceleration) and steering inputs, the user will converge on the data that best match the known accident site evidence (usually rest positions, skidmarks and vehicle damage).

In addition to vehicle-to-vehicle collisions, EDSMAC4 may also be used for many types of barrier collisions, including pole impacts.

Users of EDCRASH will find it convenient to first analyze the accident using EDCRASH to estimate the impact speeds, then use these speeds as the initial conditions for the EDSMAC4 program. The resulting confirming analysis is very powerful.

Accident researchers can use EDSMAC4 to simulate an actual staged collision test. This can be done *before* the test in order to predict or anticipate the result and help during test preparations. Test parameters may be adjusted based on EDSMAC4 results to help ensure the test is successful. After the test, the researcher can note the differences between the actual and simulated collision and modify the EDSMAC4 input in order to obtain a better match.

An extremely useful feature of EDSMAC4 is the ability to quickly and easily review the results associated with different input scenarios. Termed *what if* analysis, changes can be made to an isolated variable or set of variables in order to identify their effect on the outcome. Only the inputs that change need to be modified; the program saves all the previously entered information. For example, the sensitivity of the result to initial velocity, or post-impact driver control, can be studied by merely changing those parameters.

In HVE Studio the results play back in the 3-D viewport, and the playback can be recorded with **File › Record Animation**.

## Opening the options

In Event Information, with an EDSMAC4 event active, press **Method Options...**
under Calculation Method. The **EDSMAC Options** window opens (EDSMAC and EDSMAC4
share it). Each option is stored with the event and read by the physics engine
when the event is executed. Lengths, forces and speeds are shown in the units
set in Preferences.

## Rho Vector Initialization

**Initialize from the vehicle mesh** — HVE's *Use Vehicle Geometry for Rho Vector Init*. Default: unchecked (off), HVE's own default.

When checked, the initial lengths of the RHO (crush perimeter) vectors are measured from the vehicle's body mesh rather than from a plain rectangle built from the vehicle's exterior extents. The two agree across the middle of a face and differ at a corner, which matters for oblique impacts.

!!! warning "HVE Studio"
    EDSMAC4 needs a mesh vertex close to every rho direction (within twice the
    vector spacing) and otherwise refuses the run (stop code −6244). Real bodies
    with flat side panels fail this as well as the box-shaped body given to a
    vehicle with no mesh file. Tessellate each vehicle for the event (**Event ›
    DyMESH Options**, *Contact Mesh Preparation (per vehicle)*, or as the
    vehicle's default on the Collision tab of **Vehicle › Editors › Vehicle Mesh**; a
    maximum leg of about 0.06 m for a car); a
    refused run's status names the vehicle, the empty direction and a leg that
    works.

## Collision Parameters

**Angular Sweep Interval (deg)** (HVE's *Vector Spacing*, default 2.0 degrees), **Radial Depth Interval** (*Vector Adjustment Increment*, default 0.20 in), **Max Pressure Error** (*Vector Force Tolerance*, default 15.0 lb/in) and **Min Friction Velocity** (*Min Velocity for Friction*, default 5.0 in/sec) have the same meaning as for EDSMAC — see [EDSMAC Calculation Options](CalcOptEDSMAC.md).

The minimum friction velocity is the relative tangential surface velocity at which the full inter-vehicle friction is achieved. Below it the friction force scales linearly with sliding velocity: the effective friction coefficient becomes $\mu\,(v_t / v_{min})$.

## Inter-Vehicle Friction

Default: 0.55. EDSMAC4 takes the collision friction coefficient **per vehicle pair**. In HVE Studio the **Inter-Vehicle Friction** value in this window is the event's value, and the **Per-pair override** grid below the restitution coefficients sets a different value for any pair (blank = use the event value).

!!! note "HVE Studio"
    In HVE the per-pair value is set in the Vehicle Mesh dialog. In HVE Studio it
    is the per-pair grid in this window.

## Restitution

**Restitution Constant** (default 0.04606), **Restitution Linear Coef** (default 0.0017547 1/in) and **Restitution Quadratic Coef** (default 0.000016711 1/in²) — the constant, linear and quadratic terms of the parametric restitution model, e(δ) = c0 − c1·δ + c2·δ². Restitution is applied only below the crush depth c1/(2·c2), which the window shows. The coefficients are shown per inch or per centimeter, following the length unit set in Preferences.

## Inter-Vehicle Connection

Default: **Adjust Both Equally**. When a tow vehicle and trailer are connected, the heights of their connection points may not match. If the mismatch exceeds 0.1 in, this option selects how the gap is closed at event initialization — by adjusting the connection points' z-coordinates on the vehicles, not by moving the vehicles themselves. Where the heights already agree all four choices behave identically.

- **Manual (User-Adjusted)** — No automatic adjustment. On a mismatch the run **stops** with a bad-connection-height error: the heights you entered do not meet.
- **Adjust Tow Vehicle** — The tow vehicle's rear connection height is adjusted to meet the trailer's.
- **Adjust Trailer** — The trailer's front connection height is adjusted to meet the tow vehicle's.
- **Adjust Both Equally** — Each connection height is adjusted by half of the mismatch.

Read by EDSMAC4 only (SIMON, EDVDS and EDVTS do not read it, as in HVE). It has no effect on a single vehicle.

## Connection Model

Default: **Use heavier vehicle**. Selects how the connection (hitch) constraint stiffness and damping are derived when computing the forces between connected vehicles:

- **Use both vehicles** — Spring rate and damping are derived from the *lighter* of the two vehicles' weights.
- **Use heavier vehicle** — Spring rate and damping are derived from the heavier vehicle's weight.
- **Use tow vehicle properties** — The tow vehicle's hitch stiffness and damping (Vehicle Connections › Rear connection properties) are used directly.

It applies only to an articulated pair. EDSMAC4 has no connection failure time (SIMON's options have one).

## Hydroplane Model

Default: **Off**. Choices:

- **Off** — No hydroplaning effects.
- **NASA** — The NASA (Horne) hydroplaning model is applied at each tire traveling over a water polygon. The model predicts the hydroplaning speed from the tire's inflation pressure alone: a tire hydroplanes when its forward ground-plane speed exceeds $182.16\sqrt{P}$ in/sec, with $P$ in lb/in² (equivalently $10.35\sqrt{P}$ mph). Above that speed the tire's friction multiplier switches from the surface friction to the friction assigned to the water polygon, sharply reducing the available longitudinal and lateral tire forces.

  The friction multiplier is applied to both the peak and sliding friction coefficients taken from the tire's friction tables, so hydroplaning reduces the tire force available longitudinally *and* laterally — braking, drive traction and cornering capability are all lost together.

  > **NOTE:** The friction reduction described above is the whole of the model's effect. The extra drag of displacing water is not modeled.

- **NASA-TTI (not supported by EDSMAC4)** and **Gallaway (not supported by EDSMAC4)** — offered because an imported case can carry them; both are available in SIMON (see [SIMON Calculation Options](CalcOptSIMON.md)).

!!! warning "Refused by the engine"
    EDSMAC4 implements only Off and NASA. With **NASA-TTI** or **Gallaway**
    selected the event does not run: EDSMAC4 refuses it before it starts (stop
    code −5520), and the window says so while either is selected. HVE's fifth
    model, Blythe-Day, is not offered for EDSMAC4.

Hydroplaning needs standing water: water polygons in the environment.

## Accident History

Selects the criterion used to detect the beginning and end of each collision phase reported in the Accident History (damage ranges, delta-V, peak acceleration):

- **Impact Force** (default) — A collision phase is bounded by the presence of inter-vehicle collision force. Impact is declared on the first timestep on which collision force acts; separation is declared one timestep after it ceases.
- **Acceleration** — A collision phase is bounded by the vehicle's total acceleration exceeding the **Threshold (g)** value. The threshold field (1 g by default, the environment's gravity) is enabled only when this basis is selected. Impact is declared when either vehicle's total acceleration exceeds the threshold; separation is declared after both vehicles have remained below it for six consecutive timesteps.

In both cases the vehicles' perimeters must also overlap before impact can be declared — the acceleration test is an additional condition, not a substitute for contact.

> **NOTE:** The acceleration used by the Acceleration basis is the vehicle's *total* acceleration, which includes tire forces. A threshold low enough that hard braking or cornering exceeds it on its own can prevent separation from ever being declared, leaving the event in the collision phase — and at the collision timestep — for the remainder of the run.

> **NOTE:** EDSMAC4 reads the Threshold value whichever basis is selected; it also sets the minimum acceleration at which an acceleration peak is recognized and delta-V accumulated in the Traditional damage data format.

!!! note "HVE Studio"
    The same option exists for SIMON, but the two engines store it with
    **opposite** meanings. Each window is labeled for its own engine, so choose
    by the label, not by the position in the list.

!!! warning "HVE report defect"
    EDSMAC4's own report prints the **opposite** basis to the one used in the
    *Accident History Basis* row of its Collision Parameters table. This is
    HVE's behavior and is reproduced. The *Coll Accel Threshold* row, which is
    printed only on the Acceleration basis, is the row to trust.

See [EDSMAC4 — Impact and Separation Times](../programs/EDSMAC4/04-calculation-method.md#impact-and-separation-times) for the full description.

## Damage Data Format

Default: **Collision Data**. Choices:

- **Traditional** — Damage is reported in the traditional EDSMAC-style damage-profile format: damage ranges along the crush perimeter, each with a CDC, PDOF, total delta-V, time of peak acceleration and peak acceleration. The severity figures are derived from peaks in the vehicle's acceleration history.
- **Collision Data** — Damage is reported using HVE's extended Collision Data format: one row per collision pulse, with the vehicle struck, the pulse start and end times and duration, peak acceleration, peak collision force, delta-V and PDOF, followed by separate damage-profile and crush tables. The severity figures are derived from the inter-vehicle collision force and the accumulated velocity change. This is the record the Damage Studio reads.

This option selects the calculation as well as the layout of the damage record. The two methods are independent and will not give identical PDOF, delta-V or peak acceleration values; see [EDSMAC4 — Collision Severity Results](../programs/EDSMAC4/04-calculation-method.md#collision-severity-results-pdof-delta-v-and-peak-acceleration). The Traditional format is retained for comparison with results from earlier releases, and is only available for events with more than one vehicle. The vehicles' motion does not depend on it.

!!! warning "Not in HVE Studio"
    The **Include Free Space** check box. HVE Studio always runs EDSMAC4 with actual crush (free space not included).

## Steer DOF

!!! warning "Not in HVE Studio"
    HVE's EDSMAC4 **Steer DOF** option (Off / Normal / Append / AutoStart) is
    not offered: HVE Studio runs EDSMAC4 with the steer degree of freedom **Off**,
    so the wheels follow the driver steer table. If an imported HVE case stores
    another value, it is ignored and the run status says so.

## Terrain Search Options (Get Surface Information)

The old help ended with three undocumented entries — *From First Polygon*, *From Previous Polygon* and *By Elevation*. These select how the terrain polygon database is searched beneath each tire at every timestep. In HVE Studio they are set per event in the **Road Surface Search** section of [Event Information](../09-events-driver-controls/EventInfo.md#road-surface-search):

- **All triangles - first hit in file order** — *From First Polygon*: the entire database is searched in order from the first polygon; the first polygon containing the search point is used. Simple but slowest for large terrains.
- **Track the previous polygon** — *From Previous Polygon* (and the default): the search starts at the polygon found on the previous timestep and spreads outward through the database, returning on the first hit. Fast, but friction-zone precedence is not enforced (water polygons are still checked first).
- **Track the previous polygon, friction zones first** — *From Previous Polygon, Sorted*: water, curb and friction-zone polygons are checked first, so friction zones take precedence over the underlying road surface, then the search proceeds from the previous polygon.

!!! warning "Not in HVE Studio"
    *By Elevation* and the search **Direction** settings are not offered.

## DyMESH

EDSMAC4 does not use the DyMESH 3-D collision algorithm; the DyMESH options apply to SIMON events only.
